# i-Retail Coffee One Love

Текущая рабочая версия: **0.5.36-s2-catalog-money**.

Android-проект теперь расположен непосредственно в корне репозитория. Дополнительный каталог
`iRetail_Android_UI_v0.5.8_smartskypos_probe_source` больше не используется.

## Структура

Основные каталоги:

- `app/` — основное Android-приложение i-Retail;
- `kozenBridge/` — мост Kozen / SmartSkyPOS;
- `kozenRecoveryBridge/` — безопасное восстановление состояния платежей;
- `jl22AoaProbe/`, `jl22AoaRecovery/` — диагностические приложения JL22;
- `docs/` — контракты, отчёты и история исследований;
- `tools/` — проверочные и служебные сценарии;
- `test_reports/` — сохранённые результаты испытаний;
- `.github/workflows/` — автоматические проверки и сборки.

## Сборка под Windows

Из корня репозитория:

`BUILD_WINDOWS_CLI.bat`

Сценарий собирает debug APK и сохраняет копию в `dist/`.

## Контрактный этап S1

В версии 0.5.34 был завершён первый программный этап S1:

- неподтверждённые способы оплаты не объявляются успешными;
- подтверждённый Kozen-платёж отделён от фискализации;
- локальный суррогат фискального чека удалён;
- выдача, стакан и разогрев не возвращают фиктивный успех;
- таймеры не завершают оплату или выдачу вместо реального результата.

Версия 0.5.35 перенесла проект в корень репозитория. Версия 0.5.36 реализует S2: точные суммы в копейках и безопасную замену кэша каталога только после проверки новой выгрузки.

## Проверки

Перед каждой автоматической Android-сборкой выполняются:

1. проверка корневой структуры 0.5.35;
2. проверка инвариантов S1;
3. проверка S2 по каталогу и денежной точности;
4. `assembleDebug`.

## Важное

- минимальная версия Android основного приложения — API 23 / Android 6;
- финансовые операции не должны автоматически повторяться после неопределённого результата;
- wire-протоколы SmartSkyPOS и Vendotek нельзя менять без отдельного согласования;
- Multicard на текущем этапе не интегрируется.


## Проверка живого каталога

Для проверки реального обмена с I-Retail на Android используется:

`S2_01_BUILD_INSTALL_CATALOG_AUDIT.bat`

Сценарий собирает и устанавливает APK, запускает приложение, ждёт обновления каталога и формирует ZIP-отчёт в `test_reports\s2_catalog\`. Успешная сборка сама по себе не считается доказательством доступности живого API.
