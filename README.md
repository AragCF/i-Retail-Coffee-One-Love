# i-Retail Coffee One Love

Текущая рабочая версия: **0.5.40-api-curl-audit**.

Android-проект теперь расположен непосредственно в корне репозитория. Дополнительный каталог
`iRetail_Android_UI_v0.5.8_smartskypos_probe_source` больше не используется.

## Структура

Основные каталоги:

- `app/` — основное Android-приложение i-Retail;
- `kozenBridge/` — мост Kozen / SmartSkyPOS;
- `kozenRecoveryBridge/` — безопасное восстановление состояния платежей;
- `jl22AoaProbe/`, `jl22AoaRecovery/` — диагностические приложения JL22;
- `docs/` — контракты, отчёты и история исследований;
- `tools/` — проверочные и служебные сценарии;
- `test_reports/` — сохранённые результаты испытаний;
- `.github/workflows/` — автоматические проверки и сборки.

## Сборка под Windows

Из корня репозитория:

`BUILD_WINDOWS_CLI.bat`

Сценарий собирает debug APK и сохраняет копию в `dist/`.

## Контрактный этап S1

В версии 0.5.34 был завершён первый программный этап S1:

- неподтверждённые способы оплаты не объявляются успешными;
- подтверждённый Kozen-платёж отделён от фискализации;
- локальный суррогат фискального чека удалён;
- выдача, стакан и разогрев не возвращают фиктивный успех;
- таймеры не завершают оплату или выдачу вместо реального результата.

Версия 0.5.35 перенесла проект в корень репозитория. Версия 0.5.36 реализует S2: точные суммы в копейках и безопасную замену кэша каталога только после проверки новой выгрузки. Версия 0.5.37 добавляет только локальный безопасный черновик будущего заказа без сетевой отправки. Версия 0.5.38 провела живую приёмку: S3 DRY_RUN принят, а S2 не получил живой ZIP и ушёл на content XML. Версия 0.5.39 добавляет безопасную диагностику причины отказа живого каталога. Версия 0.5.40 добавляет независимую Windows/curl-проверку документации, авторизации и загрузки каталога теми же вызовами, что использует Android.

## Проверки

Перед каждой автоматической Android-сборкой выполняются:

1. проверка корневой структуры 0.5.35;
2. проверка инвариантов S1;
3. проверка S2 по каталогу и денежной точности;
4. проверка безопасного черновика S3;
5. проверка диагностического выпуска 0.5.39;
6. проверка Windows/curl-аудита 0.5.40;
7. синтаксическая проверка PowerShell;
8. `assembleDebug`.

## Важное

- минимальная версия Android основного приложения — API 23 / Android 6;
- финансовые операции не должны автоматически повторяться после неопределённого результата;
- wire-протоколы SmartSkyPOS и Vendotek нельзя менять без отдельного согласования;
- Multicard на текущем этапе не интегрируется.


## Проверка живого каталога

Для проверки реального обмена с I-Retail на Android используется:

`S2_01_BUILD_INSTALL_CATALOG_AUDIT.bat`

Сценарий собирает и устанавливает APK, запускает приложение, ждёт обновления каталога и формирует ZIP-отчёт в `test_reports\s2_catalog\`. Успешная сборка сама по себе не считается доказательством доступности живого API.


## Объединённая приёмка S2 + S3

Для одного безопасного живого прогона используется:

`S23_01_BUILD_INSTALL_ACCEPTANCE_AUDIT.bat`

Сценарий собирает и устанавливает APK один раз, ждёт обновления каталога, затем просит добавить товары и открыть экран способов оплаты. Выбирать способ оплаты не нужно и нельзя: финансовая операция в этом тесте не требуется.

Результат сохраняется в `test_reports\s23_acceptance\S23_ACCEPTANCE_*.zip`.


## Диагностика отказа живого каталога

Живой отчёт v0.5.38 показал `success=false source=content XML`, поэтому S2 пока не принят.

Для следующего безопасного прогона используется:

`S2_02_CATALOG_DIAGNOSTICS.bat`

Сценарий:
- сам ищет JL22 по полной ADB-сигнатуре `product:octopus_jetinno model:UniWin_M190 device:octopus-jetinno`;
- если однозначного совпадения нет, показывает нумерованный список Android-устройств и просит выбрать устройство;
- даже единственное найденное устройство проверяется по сигнатуре;
- собирает и устанавливает APK;
- не включает реальный POS;
- фиксирует безопасный этап и причину отказа каталога без секретов.

Для загрузки последнего отчёта в Git используется:

`S2_03_PUBLISH_LATEST_DIAGNOSTICS.bat`


## Независимая Windows/curl-проверка Retail API

Для проверки API напрямую с Windows, без Android и ADB:

`RAPI_01_FETCH_DOCS_AND_TEST_CATALOG.bat`

Сценарий автоматически:

1. сохраняет текущую документацию `my.i-retail.com/api/apidoc/actual`;
2. выполняет авторизацию тем же форматом запроса, что Android;
3. выполняет загрузку каталога тем же маршрутом и набором полей;
4. сохраняет безопасный отчёт;
5. проверяет отчёт на утечку учётных данных;
6. автоматически делает commit и push ZIP-отчёта в Git.

Отдельный повтор публикации последнего отчёта:

`RAPI_02_PUBLISH_LATEST_API_AUDIT.bat`

Сырое тело авторизации и access token в Git не попадают.
