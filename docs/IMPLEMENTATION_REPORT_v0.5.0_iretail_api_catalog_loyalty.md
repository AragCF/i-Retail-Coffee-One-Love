## Цель итерации

Подготовить Android-приложение к работе с реальным меню I-Retail вместо меню, взятого из дизайна, и заложить первый рабочий контур лояльности.

## Как теперь грузится меню

1. При запуске приложение сначала пытается прочитать сохранённый ZIP-каталог из внутренней памяти приложения.
2. Если кэша нет, временно показывает прежний XML-каталог из `content/main-screen.xml`.
3. После построения интерфейса запускается фоновая загрузка I-Retail:
   - `POST /api/user/authentication`;
   - `POST /api/iretail/catalog/download-actual-zip`.
4. ZIP сохраняется во внутреннюю память приложения.
5. Из ZIP читаются:
   - `categories.json`;
   - `offers_0000.json`.
6. Из предложений строятся объекты `Product`.
7. Экран каталога перерисовывается живыми карточками поверх PNG-макета.

## Как подключена лояльность

Ввод с экрана лояльности теперь уходит в сетевой слой. Приложение пробует:

1. `iretail/client/get-coupons-and-balance` — для телефона/email.
2. `ibonus/client/get-new` с `ident`.
3. `ibonus/client/get-new` с `external_id`.

Если клиент найден, экран переходит в профиль лояльности. Если клиент не найден, включается локальный демонстрационный режим, чтобы верстка и сценарий не ломались до получения тестового покупателя.

## Что ещё не сделано

- Не подключено реальное списание бонусов при создании заказа.
- Не подключено начисление бонусов после оплаты.
- Не подтверждён сценарий по QR/token клиента.
- Не сделана привязка устройства через код активации.
- Не подключены боевые POS/MDB/фискальные команды.

## Что нужно проверить на машине Андрея

1. Собрать APK.
2. Запустить приложение с интернетом.
3. Дождаться сообщения `I-Retail: загружено ... товаров`.
4. Убедиться, что на главном экране вместо кофе появились товары из I-Retail.
5. Добавить несколько товаров в заказ.
6. Проверить корзину, прокрутку, удаление, изменение количества.
7. Открыть лояльность и проверить ввод кода.
8. Прислать журнал/скриншоты, если загрузка каталога не прошла.
