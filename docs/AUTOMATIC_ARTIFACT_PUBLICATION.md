# Автоматическая публикация диагностических артефактов

Дата: 25.09.2026.

## Правило проекта

Любой новый рабочий/диагностический сценарий, который создаёт итоговый ZIP, журнал или отчёт для последующего анализа, должен по завершении сам:

1. завершить собственную проверку безопасности/редактирования секретов;
2. вычислить SHA-256 итогового артефакта;
3. добавить в Git **только** сам артефакт и его SHA-256 sidecar;
4. создать отдельный commit;
5. выполнить push в текущую рабочую ветвь;
6. вывести `AUTO_PUBLISH_OK`.

Пользователь не должен вручную загружать готовые диагностические ZIP в чат.

## Общий механизм

Использовать:

`tools/Publish-TestArtifact.ps1`

Обязательные свойства:

- отказ при detached HEAD;
- отказ, если Git index уже содержит чужие staged changes;
- артефакт обязан находиться внутри репозитория;
- не используется `git add .`;
- в commit попадают только явный артефакт и `.sha256.txt`;
- существующие незакоммиченные файлы пользователя не подхватываются;
- при ошибке push локальный commit сохраняется и сценарий возвращает ошибку.

## Порядок анализа

После успешного сценария достаточно сообщить ChatGPT имя сценария/ветки. Артефакт следует читать непосредственно из Git.

Ручная передача файла допускается только как аварийный обходной путь, если автоматическая публикация действительно не сработала.
