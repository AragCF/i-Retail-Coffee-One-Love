# Vendotek VT — итог интеграции на 16.09.2026

## Краткий итог

Интеграция транспортного и протокольного уровня с Vendotek **подтверждена на реальном оборудовании**.

Работают оба пути связи:

1. `JL22 Android 6 -> USB Host -> FTDI FT232R -> /dev/ttyUSB0 -> VTK -> Vendotek`;
2. `Windows 10 -> FTDI VCP COM24 -> VTK -> Vendotek`.

На обоих путях Vendotek корректно отвечает на `IDL` и `STATUS`, CRC и BER-TLV разбираются корректно.

Текущий блокер находится **выше транспортного уровня**: терминал устойчиво сообщает

```text
STATE=BUSY,NOT_READY;READY,DESCRIPTION=IN_SERVICE
```

и не переходит в состояние, пригодное для первой финансовой операции. По совокупности результатов наиболее вероятен незавершённый этап провизионирования терминала: регистрация в TMS, тестовый эквайринг, TID/MID, банковский профиль, ключи и/или сетевые параметры.

До подтверждения провизионирования `VRP` и любые финансовые операции не выполняются.

---

## 1. Аппаратный интерфейс

Реальный экземпляр Vendotek подключается как FTDI FT232R:

```text
VID:PID = 0403:6001
Manufacturer = FTDI
Product = FT232R USB UART
FTDI serial = A507YBKB
```

Маркировка на самом терминале:

```text
220000047601
```

Эту величину следует называть маркировкой/серийным номером с наклейки, пока сам POS не вернул SN протокольно через `POS_PARAMS`.

### JL22 / Android 6

Ядро штатно загружает:

```text
ftdi_sio
/dev/ttyUSB0
```

Права устройства позволяют приложению открыть последовательный порт. SELinux на тестовой JL22 выключен. Для установки параметров `115200 8N1` на данном образе Android диагностические программы используют имеющийся factory `su`, потому что прямой запуск `/sbin/busybox stty` из UID приложения запрещён.

Это временная особенность диагностической реализации; промышленный транспорт не должен зависеть от запуска shell/root из UI.

### Windows 10

FTDI VCP установлен и исправно перечисляется:

```text
USB Serial Port (COM24)
PNPDeviceID=FTDIBUS\VID_0403+PID_6001+A507YBKBA\0000
Status=OK
ConfigManagerErrorCode=0
FTDI driver=2.12.36.20
INF=oem91.inf
```

Предыдущий `COM7` оказался Bluetooth-портом и к Vendotek отношения не имеет.

## 2. Последовательные параметры

Подтверждённый режим:

```text
115200 baud
8 data bits
No parity
1 stop bit
No flow control
```

То есть `115200 8N1`.

---

## 3. VTK framing

Подтверждён реальный двусторонний обмен VTK.

Последовательный кадр:

```text
0x1F
Length, 2 bytes, big-endian
Discriminator, 2 bytes
BER-TLV payload
CRC16-CCITT, 2 bytes, big-endian
```

Направления:

```text
0x96FB  VMC -> POS
0x97FB  POS -> VMC
```

CRC16-CCITT использует начальное значение `0xFFFF`.

Кодек прошёл опубликованный эталон IDL-кадр из руководства VTK с CRC:

```text
977E
```

---

## 4. Подтверждённый IDL

### Через JL22

Реальный IDL был отправлен через `/dev/ttyUSB0`, а Vendotek вернул:

```text
1f000a97fb010349444c030130d90c
```

Разбор:

```text
discriminator = 0x97FB
crcOk = true
message = IDL
operation = 0
```

### Прямо через Windows COM24

Прямой Windows-тест полностью подтвердил тот же канал без JL22:

```text
COM_PORT=COM24
COM_OPEN_OK baud=115200 data=8 parity=None stop=1 flow=None
IDL_TX ...
RX discriminator=0x97fb crcOk=True message=IDL operation=0
VTK_IDL_OK operation=0
```

Итог:

```text
OUTCOME=COM_VTK_OK
VENDOTEK_WINDOWS_COM_OK
```

Таким образом, JL22 не является обязательным для диагностики Vendotek: тот же VTK можно отлаживать напрямую из Windows через `COM24`.

---

## 5. STATUS

STATUS стабильно работает как через JL22, так и напрямую через Windows.

Фактический ответ:

```text
STATE=BUSY,NOT_READY;READY,DESCRIPTION=IN_SERVICE
```

После холодного перезапуска терминала было получено восемь последовательных одинаковых STATUS примерно раз в 10 секунд.

Следовательно, `IN_SERVICE / NOT_READY` — не кратковременная стадия загрузки, а устойчивое состояние данного экземпляра/профиля терминала.

Для первой продажи мы считаем допустимым только два последовательных чистых `READY` без:

```text
BUSY
NOT_READY
DISABLED
IN_SERVICE
```

---

## 6. System Information

Были безопасно проверены:

```text
STATUS
POS_PARAMS
BANK_PARAMS
NET_PARAMS
```

`STATUS` возвращает содержательную строку.

На `POS_PARAMS`, `BANK_PARAMS`, `NET_PARAMS` данный экземпляр отвечает обычным корректным `IDL`, но не возвращает ожидаемое содержимое SystemInformation.

Это не ошибка FTDI, framing или CRC: транспорт на этих же сессиях работает.

---

## 7. Сервисная Wi-Fi сеть

Пассивно сравнивался Wi-Fi эфир при выключенном и включённом Vendotek.

Результат:

```text
Vendotek OFF: CF_Festival
Vendotek ON:  CF_Festival
New SSID candidates: NONE
```

Отдельная видимая сервисная точка доступа не появилась.

Это не доказывает отсутствия Wi-Fi меню как функции прошивки: для VT точка доступа может требовать отдельной процедуры активации.

## 8. TMS keepalive

С явным разрешением оператора один раз был отправлен:

```text
POS Management data = A
```

Переданный реальный кадр:

```text
1f002096fb010349444c11143230323630393136543134343735312b303330301001415dbb
```

Vendotek почти сразу ответил обычным корректным IDL.

За следующие примерно 45 секунд не было обнаружено:

```text
ack A
CON
DAT
DSC
Stage 921
Stage 922
```

STATUS после этого не изменился:

```text
STATE=BUSY,NOT_READY;READY,DESCRIPTION=IN_SERVICE
```

Классификация:

```text
VTK_TMS_RESULT NO_TMS_ACTIVITY_OBSERVED
```

Это не доказывает отсутствия TMS-функции как таковой. Наиболее вероятные варианты: терминал не зарегистрирован в TMS, не имеет TMS-профиля, не привязан к нужному контуру либо данная конфигурация прошивки требует другого этапа активации.

## 9. Что уже можно считать завершённым

Подтверждены:

- физическое подключение Vendotek к JL22 по USB;
- FTDI FT232R;
- Linux driver `ftdi_sio`;
- `/dev/ttyUSB0`;
- прямой Windows FTDI VCP `COM24`;
- `115200 8N1`;
- VTK framing;
- BER-TLV;
- CRC16-CCITT;
- направления `96FB / 97FB`;
- реальный `IDL`;
- реальный `STATUS`;
- двусторонний обмен на JL22;
- двусторонний обмен напрямую на Windows;
- устойчивость состояния `IN_SERVICE` после холодной загрузки;
- отсутствие отдельной видимой Wi-Fi точки в пассивном тесте;
- отсутствие наблюдаемой TMS-сессии после одного разрешённого `A`.

Транспортная часть интеграции Vendotek считается **доказанной**.

---

## 10. Что пока не считается завершённым

Не подтверждены:

- регистрация данного экземпляра в TMS;
- тестовый TID;
- MID/merchant profile;
- банковский/эквайринговый профиль;
- криптографические ключи;
- параметры процессинга;
- рабочий сетевой профиль POS;
- чистый `READY`;
- реальный `VRP`;
- ответ финансовой операции;
- правильная цепочка `VRP -> результат -> FIN` на реальном эквайринге;
- возврат/отмена/сверка — намеренно не проверялись.

---

## 11. Безопасность финансовых операций

До провизионирования финансовые команды запрещены.

После получения рабочего тестового профиля первый платёж должен выполняться как отдельный staged-тест:

1. холодная загрузка Vendotek;
2. `IDL`;
3. два последовательных чистых `READY`;
4. уникальный operation number;
5. ровно один `VRP` на минимальную сумму тестового контура;
6. никакого автоматического повторения при неопределённом результате;
7. сохранение всех сырых кадров;
8. `FIN` только в соответствии с реальным результатом операции и правилами VTK;
9. при неопределённом состоянии сначала восстановление/запрос состояния, а не повтор продажи.

---

## 12. Что запросить у поставщика / эквайера

Для экземпляра с маркировкой `220000047601` необходимо подтвердить:

1. зарегистрирован ли он в TMS;
2. привязан ли он к **тестовому** платёжному контуру;
3. какой тестовый TID назначен;
4. какой MID/merchant profile назначен;
5. какой банк/эквайер должен использоваться;
6. загружен ли банковский профиль;
7. загружены ли необходимые ключи/сертификаты;
8. настроен ли процессинг и сетевой профиль;
9. какие операции разрешены;
10. какой STATUS должен возвращаться у полностью готового VT;
11. должна ли команда `POS Management data=A` запускать TMS-сессию на данной прошивке;
12. должны ли поддерживаться `POS_PARAMS`, `BANK_PARAMS`, `NET_PARAMS`;
13. как штатно активируется сервисная Wi-Fi точка на безэкранном VT.

---

## 13. Следующее действие после ответа поставщика

После того как поставщик подтвердит провизионирование тестового контура:

```text
Vendotek power-cycle
-> IDL
-> STATUS x2
-> clean READY
-> staged VRP
-> result
-> FIN по правилам VTK
```

До этого дальнейшие финансовые испытания не дают полезной информации о качестве нашей интеграции.
