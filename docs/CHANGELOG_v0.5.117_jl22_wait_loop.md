# CHANGELOG v0.5.117 — ожидание восстановления JL22

Дата: 24.09.2026.

## Причина выпуска

Комбинированный прогон v0.5.116 успешно:

- установил Kozen Bridge 0.5.6;
- сохранил сетевой ADB Kozen;
- собрал и установил i-Retail;
- получил `EVENT_QUEUE_OK`;
- подтвердил безопасный обмен `peek → ACK` без финансовых команд.

После этого перед запуском экранного QR DRY_RUN JL22 оказался `offline`, и прежний `MAIN_30` завершился кодом 13.

## Исправление

Добавлен общий сценарий:

`tools/WAIT_FOR_JL22.bat`

Поведение:

1. ищет только настоящий JL22 по полной ADB-сигнатуре;
2. если JL22 уже `device` — немедленно продолжает;
3. если JL22 найден как сетевой `offline` — один раз пробует `adb connect`;
4. если связи всё ещё нет — показывает устройства и ждёт пользователя;
5. любая клавиша повторяет попытку;
6. число попыток не ограничено;
7. `Ctrl+C` позволяет штатно остановить пакет.

Механизм подключён к:

- `MAIN_30_SBP_DRYRUN_UI_TEST.bat`;
- `MAIN_34_SBP_EVENT_QUEUE_SYNTHETIC_TEST.bat`;
- `MAIN_35_KOZEN_BRIDGE_UPGRADE_AND_SBP_QUEUE_TEST.bat`.

`MAIN_30` и `MAIN_34` дополнительно перепроверяют JL22 после сборки и непосредственно перед установкой APK.

Финансовая логика не изменена. Реальный `qrPayment` остаётся выключен.
