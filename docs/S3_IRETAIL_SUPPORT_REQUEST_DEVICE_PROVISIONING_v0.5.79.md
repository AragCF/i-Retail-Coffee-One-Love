# S3 — запрос в поддержку I-Retail по созданию/активации кассового устройства

Версия проекта: 0.5.79  
Дата: 22.09.2026  
Статус: WAITING_FOR_IRETAIL_SUPPORT

## Коротко

Для завершения S3 нам нужен серверный device типа, пригодного для `order/synchronize`.

Сейчас доказано:
- `profile_id = 2512`;
- `channel_id = 5676`;
- в обычном `iretail/device/get-by-channel-id` видна только `coffee_machine` с `device_id = 3476`;
- старый configured `device_id = 6287` не подтверждён как актуальная касса;
- `device/register(device_code)` для coffee_machine 3476 сервер отверг;
- `device/register-external-system(external_code)` для coffee_machine 3476 сервер тоже отверг;
- документация `device/register` / `register-external-system` обещает вернуть только типы `workplace_cashier` или `self_service_terminal`;
- документация `admin/device/create` показывает, что кассовое устройство создаётся отдельно;
- текущая учётная запись успешно проходит обычный `user/authentication`, но не проходит `user/admin-authentication`;
- `user/get-permissions` для текущего пользователя возвращает только `right.managementOrderRefund`;
- административного доступа у нас нет.

## Что нужно от I-Retail

Просим поддержку определить правильный серверный сценарий для проекта Coffee One Love:

- Android UI работает на кофемашине Jetinno JL22;
- пользователь выбирает напиток и оплачивает его через подключённый внешний POS-терминал;
- после подтверждённой оплаты приложение должно синхронизировать заказ в I-Retail через `order/synchronize`;
- требуется штатный источник:
  - `device_id`;
  - `device_inner_id`;
  - `type_slug`;
  - `order_counter`;
  - `operation_counter`;
  - `refund_counter`;
  - текущей смены / `shift_id`;
  - `check_counter`.

## Основные вопросы поддержке

1. Какой `type_slug` следует использовать для нашего сценария:
   - `self_service_terminal`;
   - или `workplace_cashier`?

   Просим не просто назвать тип, а подтвердить, что он предназначен для unattended/self-service кофейной точки с внешним POS.

2. Есть ли уже в профиле 2512 / канале 5676 подходящее кассовое устройство?

3. Существует ли ещё `device_id = 6287`?
   - Если да — какой у него `type_slug`, статус и канал?
   - Можно ли его реактивировать и использовать?
   - Если нет — считать его устаревшим/удалённым.

4. Если подходящего устройства нет, просим:
   - либо создать его на вашей стороне;
   - либо выдать административный доступ/роль, достаточные для безопасного `admin/device/create` и read-only инвентаризации устройств.

5. После создания устройства просим предоставить штатный способ его активации:
   - нужно ли использовать `device/register(device_code)`;
   - или `device/register-external-system(external_code)`;
   - какой именно код должен применяться для выбранного типа устройства.

6. Просим подтвердить, что успешная регистрация выбранного device должна вернуть counters:
   - `order_counter`;
   - `operation_counter`;
   - `refund_counter`;
   - `date`.

7. Для обычного `device/register` документация также показывает:
   - `shift.id`;
   - `shift.check_counter`.

   Просим подтвердить, откуда их получать для выбранного варианта устройства.

8. Нужно ли сначала открыть смену вручную/в административной панели, или у self-service terminal смена создаётся автоматически?

9. Какой `service_in_slug` следует использовать для оплаты банковской картой через внешний POS-терминал?
   В текущем профиле мы видим среди кандидатов `external_plastic_cards`, но не хотим выбирать его без подтверждения.

## Что мы НЕ просим

Мы не просим:
- отключать проверки безопасности;
- выдавать нам чужие пароли;
- давать прямой доступ к базе;
- вручную менять counters;
- разрешать повторные финансовые запросы.

Нам нужен только штатный, поддерживаемый I-Retail способ создать/активировать правильную кассовую сущность для дальнейшего `order/synchronize`.

Здравствуйте.

Интегрируем приложение Coffee One Love с I-Retail для самообслуживаемой кофейной точки.
