# ВПП / SmartSkyPOS — обращение по устойчивому отказу rc=99

Дата: 24.09.2026  
Проект: Coffee One Love / i-Retail / Jetinno JL22 + Kozen P12  
Статус: **PROVIDER_BLOCKER_CONFIRMED**

## 1. Краткое описание

Карточный платёж на Kozen P12 стабильно завершается определённым отказом SmartSkyPOS:

- `approved=false`;
- `rc=99`;
- `message=Отказано`;
- сумма текущей контрольной операции: `1.00 RUB`.

Отказ подтверждён повторным read-only чтением конкретной последней транзакции через SmartSkyPOS.

## 2. Что уже исключено

### Android UI / i-Retail

Основной интерфейс успешно:
- формирует заказ на 1,00 ₽;
- выполняет read-only preflight;
- видит SmartSkyPOS READY;
- видит актуальный payment route;
- передаёт ровно одну финансовую попытку после ручного действия пользователя.

### JL22 ↔ Kozen USB/AOA

Транспорт подтверждён:
- PING/PONG;
- INFO;
- GET_STATE;
- GET_TERMINAL_DATA;
- чтение истории транзакций;
- повторное адресное чтение по receipt.

Следовательно, USB/AOA не является причиной `rc=99`.

### Прямой вызов на самом Kozen

14.09.2026 был выполнен отдельный локальный диагностический платёж непосредственно на Kozen, без JL22 и без AOA.

Результат был тем же:
- `approved=false`;
- `rc=99`;
- `amount=1.00`.

В истории терминала также присутствует операция на `57.00 RUB` с тем же `approved=false / rc=99`.

Это исключает JL22 и AOA как источник отказа.

## 6. Что требуется от ВПП

Просим:
- проверить карточный acquiring-профиль терминала;
- расшифровать `rc=99`;
- подтвердить тестовый или боевой статус профиля `VPP_BETA_TMS_V1`;
- при необходимости удалённо перевести терминал на корректный production profile;
- подтвердить готовность к контрольной операции 1,00 ₽.

## 7. Безопасность

В публичную диагностику не включаются:
- PAN;
- track data;
- PIN;
- authCode;
- RRN;
- полные terminal/TMS identifiers;
- секреты/ключи.

Финансовые повторы до получения нового явного разрешения пользователя запрещены.
