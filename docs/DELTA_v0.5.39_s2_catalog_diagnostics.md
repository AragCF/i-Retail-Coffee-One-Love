# DELTA v0.5.39 — диагностика живого каталога S2

Дата: 20.09.2026  
Основа: живой отчёт v0.5.38, где S3 DRY_RUN принят, а S2 вернул `success=false source=content XML`.

## Цель

Не менять бизнес-логику каталога, оплаты или заказа. Добавить безопасную, структурированную диагностику причины, по которой живой ZIP-каталог I-Retail не загрузился на JL22.

## 🟢 Добавлено

- этап отказа каталога:
  - `authentication`;
  - `download`;
  - `parse`;
  - `validate`;
  - `cache`;
  - `unknown`;
- безопасная причина без паролей, access token, client secret и тела HTTP-ответа;
- диагностический журнал `IretailCatalog` с полями `failureStage` и `failureReason`;
- отдельный живой сценарий `S2_02_CATALOG_DIAGNOSTICS.bat`;
- обязательное определение JL22 по сигнатуре ADB с нумерованным меню как запасным вариантом.

## 🟡 Изменено

- версия приложения: `0.5.39-s2-catalog-diagnostics`, `versionCode 39`;
- HTTP-ошибка в диагностическом контуре представляется только кодом состояния, без публикации тела ответа;
- основной workflow дополнительно проверяет инварианты диагностического выпуска.

## 🔴 Не меняется

- URL API и имена серверных полей;
- содержимое запроса авторизации;
- правила каталога и денежной модели S2;
- S3 DRY_RUN;
- платежи, Kozen, Vendotek, фискализация;
- Multicard.

## ⚠️ Ограничение

В репозитории исторически присутствуют чувствительные учётные данные I-Retail. Этот выпуск их не публикует в новых журналах и не меняет без отдельного решения, чтобы не сломать стенд. Ротация и вынос секретов должны быть отдельным шагом.
