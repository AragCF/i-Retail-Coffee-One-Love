# Implementation Report — i-Retail Android UI MVP v0.2

## Статус

Реализован первый безопасный UI MVP в рамках `PROTOCOL_iRetail_Android_UI_v0.2.md`.

## Архитектурное решение

Интерфейс сделан как нативное Android-приложение на Kotlin. Для первого этапа экраны отображаются как полноэкранные PNG-макеты с прозрачными кликабельными зонами поверх. Это позволяет быстро получить визуально близкий интерфейс на реальной Jetinno JL22 и проверить переходы, не тратя первый цикл на ручную декомпозицию каждого макета в отдельные View-компоненты.

Это сознательное решение для v0.2. После обратной связи можно постепенно заменить ключевые экраны на настоящие компонентные Android-вёрстки без изменения внешнего сценарного контракта.

## Что входит

- `MainActivity` — один полноэкранный экранный контроллер с маршрутизацией по `Screen ID`.
- `Models.kt` — локальные модели товара, корзины, прямоугольников клика и платёжного метода.
- `MockGateways.kt` — безопасные мок-шлюзы каталога, оплаты, лояльности и исполнительного слоя.
- `mock_catalog.json` — локальный мок-каталог.
- `drawable-nodpi` — PNG-макеты, переименованные в допустимые имена ресурсов Android.
- `docs/screen_asset_map.md` — соответствие `Screen ID` → исходный PNG → Android drawable.

## Что не входит

- Реальное приготовление напитка.
- Реальная оплата.
- MDB.
- POS-протокол.
- Онлайн-касса / фискализация.
- Реальная лояльность.
- Реальный разогрев еды.
- Работа с датчиками дверцы, стаканчика, веса, полок.

## Риски и честные ограничения v0.2

1. Кликабельные зоны восстановлены по PNG-макетам и схеме переходов приближённо. На реальной JL22 их нужно проверить пальцем и поправить.
2. Визуал максимально похож на макет, потому что используются исходные PNG, но динамические значения на самих картинках пока не перерисовываются.
3. Для промышленного выпуска ключевые экраны желательно постепенно перевести из PNG-прототипа в компонентный Android UI.
4. Автозапуск, закрепление приложения как системного киоска и подпись APK пока не включены в этот архив.

## Проверка после сборки

Минимально нужно проверить:

- запуск на эмуляторе API 23;
- запуск на Jetinno JL22;
- соответствие масштаба 1080 × 1920;
- отсутствие системной панели навигации;
- работу касаний по товарам, оплате, чеку, выдаче и возврату к заставке;
- производительность перелистывания экранов;
- поведение после перезапуска приложения.
