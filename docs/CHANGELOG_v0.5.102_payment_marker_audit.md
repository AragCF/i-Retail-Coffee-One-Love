# CHANGELOG v0.5.102 — payment marker audit

Дата: 24.09.2026.

## Причина

После установки v0.5.101 сценарий обнаружил существующий файл
`files/fiscal_positive_payment_test_v1_0_1.attempt` и остановился до финансового режима.

Поскольку `adb install -r` останавливает процесс обновляемого приложения, i-Retail остался закрытым: сценарий завершился до повторного безопасного запуска интерфейса.

По имеющимся журналам нельзя автоматически заключить, что маркер соответствует реально отправленному PAYMENT. Поэтому удаление маркера или разрешение новой оплаты без дополнительной проверки запрещено.

## Добавлено

`MAIN_27_FISCAL_PAYMENT_MARKER_AUDIT.bat`:
- не собирает и не устанавливает APK;
- не отправляет PAYMENT;
- не удаляет маркер;
- не очищает платёжные SharedPreferences;
- не очищает logcat;
- сначала сохраняет `machine_mode=standalone`, `real_pos_enabled=false`;
- затем возвращает основной i-Retail на передний план;
- читает содержимое и файловую информацию маркера;
- читает долговечное платёжное состояние JL22;
- при доступном ADB читает долговечное состояние Kozen Bridge;
- собирает существующие журналы обеих сторон;
- санитизирует платёжные идентификаторы;
- создаёт локальный ZIP для анализа.

Анализатор различает:
- `UNRESOLVED_PAYMENT_PRESENT`;
- `DIRECT_PAYMENT_EVIDENCE_FOUND`;
- `MARKER_PRESENT_WITH_KOZEN_PAYMENT_HISTORY`;
- `MARKER_PRESENT_NO_DIRECT_PAYMENT_EVIDENCE`;
- `NO_MARKER`.

Ни один из результатов сам по себе не удаляет маркер и не разрешает повторный PAYMENT.
