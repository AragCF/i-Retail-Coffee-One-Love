# S3 — контрактная граница device/register

Дата: 21.09.2026. Версия: v0.5.55.

## Доказано

Опубликованная документация `/api/iretail/device/register` принимает `device_code` и возвращает:

- `device_id`;
- `channel_id`;
- `device_inner_id`;
- `counters.order_counter`;
- `counters.operation_counter`;
- `counters.refund_counter`;
- `counters.date`;
- `shift.id`;
- `shift.check_counter`.

Это именно те текущие значения, которых не хватает для доказанного `order/synchronize`.

## Почему вызов пока запрещён

Метод называется и документирован как регистрационный. Даже если практическая реализация окажется идемпотентной, текущие источники не доказывают отсутствие серверного изменения состояния.

Поэтому v0.5.55:

- не вызывает `device/register`;
- не использует старую смену 164570 как текущую;
- не использует device 3476 как текущую кассу;
- не использует configured 6287 как кассу;
- не выдумывает counters.

## Что должен дать следующий контрактный выбор

Нужно выбрать один из доказательных путей:

1. разрешить контролируемый единичный вызов штатного `device/register(device_code)` и сравнить состояние до/после;
2. получить у поставщика подтверждение семантики `device/register` или отдельный read-only метод для текущих counters;
3. не использовать offline `order/synchronize`, если актуальные counters/shift нельзя получить без нежелательного изменения состояния.

До этого сетевой `order/synchronize` остаётся запрещён.
