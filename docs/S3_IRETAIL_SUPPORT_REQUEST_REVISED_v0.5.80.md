# S3 — обновлённый запрос в поддержку I-Retail после анализа web-fiscal API

Версия: 0.5.80  
Дата: 22.09.2026

Здравствуйте.

Интегрируем Coffee One Love с I-Retail для самообслуживаемой кофейной точки.

После изучения переданной нам документации обнаружили отдельный документ «Протокол обмена данными с внешними сервисами — потребителями фискализации заказов».

В нём описан:
- POST `/api/cloud-fiscal/order/create`;
- авторизация через `api_key + login`;
- создание заказа для канала «фискализация интернет заказа»;
- последующий `getStatus`;
- callback;
- получение `invoice_url` и фискальных реквизитов.

Этот API не требует `device_id`, counters или shift во входном запросе.

Просим уточнить:

1. Поддерживается ли этот API в текущей версии I-Retail?
2. Если поддерживается — какой актуальный base URL?
3. Можно ли получить для нашего проекта `api_key` канала продаж и login?
4. В какой профиль/channel попадут заказы, созданные через cloud-fiscal API?
5. Предназначен ли этот API только для фискализации или может использоваться вместо `iretail/order/synchronize` для внешней self-service системы?
6. Если обычный бизнес-заказ всё равно должен отдельно отправляться через `order/synchronize`, просим подтвердить, какой device type и способ provisioning нужны для unattended coffee machine:
   - `self_service_terminal`;
   - или `workplace_cashier`.
7. Нужны ли для Retail order sync отдельные counters/shift, если фискализация выполняется внешним Fiscal API?
8. В более новом ТЗ у нас указан отдельный провайдер онлайн-кассы / Первый ОФД. Это актуальная рекомендуемая схема вместо старого cloud-fiscal API?

Наша архитектура разделяет:
- POS-оплату;
- Retail order sync;
- Fiscalization.

Хотим подтвердить штатный контракт каждой части, не смешивая их.

Спасибо.
