# Отчёт реализации v0.5.56 — S3 counter source audit

## Цель

До любого потенциально изменяющего серверное состояние вызова проверить всю текущую опубликованную документацию I-Retail и выяснить, существует ли документированный read-only источник актуальных:

- `order_counter`;
- `operation_counter`;
- `refund_counter`;
- `check_counter`.

## Реализация

Добавлен документационный аудит, который начинает не со списка заранее известных страниц, а с актуального `apidoc/actual/index.html`. Из него динамически извлекаются все страницы контроллеров `iretail/*`.

Каждая страница загружается обычным GET, преобразуется в текст, после чего сохраняются:

- все найденные маршруты `/api/iretail/*`;
- каждый контекст вокруг пяти counter-терминов;
- ближайший к совпадению маршрут;
- эвристическая классификация имени маршрута как read-only-кандидата, state-change-кандидата или неизвестного.

Эвристика не считается доказательством семантики и нужна только для ускорения последующего анализа.

## Безопасность

Сценарий не содержит:

- авторизации рабочего API;
- access token / client secret;
- POST-параметров curl;
- `device/register`;
- `order/synchronize`;
- операций со сменой или платежом.

## Проверка

В автоматическую сборку добавлены:

- `tools/verify_v0_5_56_s3_counter_source_audit.py`;
- `tools/Verify-S3CounterSourcePowerShell.ps1`.

## Прогресс

S3 остаётся **4/5, 80%**, поскольку версия 0.5.56 не меняет рабочий контракт — она должна доказательно закрыть вопрос о наличии либо отсутствии безопасной альтернативы `device/register`.
