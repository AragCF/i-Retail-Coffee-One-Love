# CHANGELOG v0.5.53 — исправление ложного срабатывания safety scan

Дата: 21.09.2026

## Причина выпуска

Живой запуск v0.5.52 дошёл до формирования локального отчёта, но был остановлен собственной защитой:

`Safety scan failed: secret-like value found in report`

Это произошло уже после завершения read-only API-вызовов.

## Причина

В общий поиск секретных **значений по всему отчёту** был включён `device_code`.

Для нашей конфигурации это короткое идентификатороподобное значение может совпадать с обычным публичным числовым ID, который отчёт обязан сохранить, например `configured_device_id`.

В результате safety scan не отличал:
- допустимый ID;
- секретное поле `device_code`.

## 🟢 Исправлено

Защита разделена на два уровня.

### 1. Структурная очистка

По имени поля по-прежнему обязательно удаляются:
- `device_code`;
- `external_code`;
- `pin`;
- `username`;
- телефоны/e-mail;
- персональные имена;
- serial/MAC/IP и другие чувствительные поля.

### 2. Глобальный поиск точных значений

По всему отчёту как сырые значения блокируются только:
- password;
- client_secret;
- access token.

Короткие идентификатороподобные `device_code` и login в этот поиск не входят, чтобы не создавать ложные совпадения с допустимыми ID.

При этом `device_code` и login остаются в списке редактирования ошибок curl/временных диагностических сообщений.

## 🟢 Дополнительная диагностика

При блокировке глобальным поиском теперь выводятся только имена файлов, где найден секрет, без самого секретного значения.

## 🔴 Не изменено

- API-запросы;
- read-only характер проверки;
- запрет регистрации устройства;
- запрет открытия/закрытия смены;
- запрет employee/authorize;
- запрет payment-in/create;
- запрет order/synchronize;
- запрет автоматического выбора устройства.
