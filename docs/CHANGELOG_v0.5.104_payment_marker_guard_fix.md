# CHANGELOG v0.5.104 — payment marker guard fix

Дата: 24.09.2026.

Read-only аудит доказал:
- outcome=NO_MARKER;
- Windows consumed marker отсутствует;
- JL22 unresolved payment отсутствует;
- Kozen active_request отсутствует;
- текущие PAYMENT_TX_ONCE / PAYMENT_CALL_BEGIN отсутствуют.

Следовательно, срабатывание старого MAIN_26 было ложным.

Причина: проверка использовала `ls files/fiscal_positive_payment_test_v1_0_1.attempt` и затем искала имя файла через findstr. Сообщение об отсутствии файла могло содержать то же имя и ошибочно считаться доказательством существования.

Исправлено:
- маркер читается через `cat`;
- наличие признаётся только при точной строке `contract=S3_FISCAL_POSITIVE_PAYMENT_CONTRACT_v1.0.1`;
- проверка выполняется до сборки и установки;
- после установки она повторяется как страховка;
- отсутствующий файл не может пройти проверку;
- unresolved payment state также проверяется до сборки и после установки;
- настоящий маркер автоматически не удаляется.

Финансовый контракт не расширен. Разрешена всё та же одна реальная операция на 1,00 ₽.
