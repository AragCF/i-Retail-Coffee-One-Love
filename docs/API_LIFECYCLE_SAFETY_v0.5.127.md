**Статус:** прикладной код собран, целевые JVM-тесты пройдены; установка и приёмка на JL22 не выполнялись. Это промежуточная разработческая версия безопасной API-основы, не завершённая интеграция лояльности.

## Область

Продолжение одобренного `SERVER_MANAGED_INTEGRATIONS_CONTRACT_v1.0.0.md` и `API_FIRST_PLAN_AFTER_TSO_REV2_20260926.md`. ## Изменения

1. Результаты чтения каталога, конфигурации канала и лояльности поступают через отдельный `apiResultHandler`. Очистка экранных таймеров в `openScreen()` больше не удаляет эти ответы.
2. `ApiRequestGate` допускает один активный запрос каждого вида на экземпляр Activity. Отмена актуальности ответа не освобождает занятый запросом слот до фактического завершения чтения. Повторный или чужой callback не освобождает слот нового запроса.
3. При остановке экрана результат лояльности становится неактуальным. Переход с экрана ввода, сброс пользовательской сессии и уничтожение Activity также исключают применение старого результата. Дополнительно проверяются экран и введённый код.
4. Изменения данных, полученные в остановленной Activity, не перерисовывают её немедленно. При возвращении интерфейс обновляется; повторное чтение при возвращении ограничено интервалом 30 секунд. Плановый интервал 5 минут сохранён. Это настройки клиента, не гарантии сервера.
5. Проверяется `status` обоих ответов: канала и списка служб. Отсутствующий массив `services`, неправильный тип его элементов и пустой ключ службы не считаются корректным пустым списком. Для числового флага распознаются только 0 и 1.
6. Неподтверждённое списание блокируется не только интерфейсом: `LocalLoyaltyGateway.applyBonus()` возвращает ноль, `LocalRetailOrderGateway.createOrder()` не принимает аргумент скидки за подтверждение списания, итоговая скидка UI равна нулю. Баланс остаётся информацией, а не разрешением операции.
7. Результат поиска с `success=false` или `loyaltyActive=false` не прикрепляет клиента через `loginSuccess(LoyaltyLookupResult)`.
8. Версия приложения повышена до 0.5.127, связанные текущие Windows-сценарии согласованы с этой версией. Изменённые BAT содержат только ASCII-байты, совместимые с CP866; команда `chcp` не добавлялась. Запуск BAT под Windows не выполнялся.

## Что ещё не доказано

Защита запросов действует в пределах одного экземпляра Activity; полная сериализация записи каталога между пересозданными экземплярами требует отдельной проверки. Не закончены испытания атомарного кэша, сверка корзины при изменении цены/удалении товара и подтверждение семантики серверных флагов. Формат действительно пустого серверного ZIP и конечный процесс лояльности ожидают ответов Q03/Q07/Q08. Смена модели кошельков, курс баллов и действующий метод списания не выдумывались.

APK не устанавливалась на JL22. Устойчивость при смене экранов на настоящем Android 6 ещё должна быть проверена. В основной README сохранён исторический обзор v0.5.126; текущая разработческая ревизия этой ветки определяется `app/build.gradle` и настоящим отчётом.
