# DELTA v0.5.37 — S3: безопасный черновик заказа

Дата: 20.09.2026  
Основа: утверждённый контракт 1.1.0 и правило из `NEXT_STEPS_AFTER_v0.5.6.md`: сначала сформировать заказ и проверить его без сетевой отправки.

## 🟢 Добавлено

- локальный построитель `OrderSyncDraftBuilder`;
- JSON-отчёт `order_sync_draft.json` во внутреннем каталоге приложения;
- кандидат полей из восстановленного TSO: `channel_id`, `sum`, `device_id`, `device_code`, `currency_id`, `time_create`, `products[].offer_id`, `products[].quantity`, `products[].price`;
- арифметическая проверка суммы строк заказа;
- Windows-сценарий `S3_01_BUILD_INSTALL_ORDER_DRAFT_AUDIT.bat`;
- автоматическая проверка S3.

## 🟡 Изменено

- при переходе из корзины к выбору способа оплаты приложение дополнительно сохраняет локальный черновик заказа;
- версия приложения: `0.5.37-s3-order-draft`, `versionCode 37`;
- основной Android workflow теперь проверяет root layout, S1, S2 и S3.

## 🔴 Не добавлено

- **нет** POST/HTTP-вызова `iretail/order/synchronize`;
- **нет** резервирования server order id;
- **нет** создания реальной записи заказа в I-Retail;
- **нет** автоматического платежа;
- **нет** догадок по `employee_id` и `pin`.

## ⚠️ Нерешённые поля

В черновике явно оставлены `null`:

- `id` — нужно доказать связь с `order/reserve-order-id`;
- `employee_id` — источник значения пока не подтверждён;
- `pin` — назначение и источник пока не подтверждены.

Также ещё нужно подтвердить точный формат сериализации `iretail/order/synchronize` и формат результата/идемпотентности.

## Безопасность

Черновик не содержит пароля, client secret, access token или банковских реквизитов. Платёжная операция при тесте не нужна.
