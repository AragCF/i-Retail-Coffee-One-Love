# Сверка Retail API перед Windows/curl-аудитом — v0.5.40

Дата: 20.09.2026

## Канонический источник

Техническое задание проекта указывает Retail API:

`https://my.i-retail.com/api/apidoc/actual/index.html`

Публичную страницу документации из текущей среды ChatGPT получить не удалось: внешний запрос к странице не вернул содержимое, а поисковые системы не дали индексированной копии. Поэтому точное содержимое актуальной страницы не выдумывается.

Чтобы закрыть этот пробел доказательно, Windows-аудит **первым действием** скачивает с машины пользователя:

- `index.html`;
- `api_data.js`;
- `api_project.js`.

Эти файлы попадают в безопасный отчёт и затем в Git, после чего фактическую актуальную документацию можно сравнить с приложением построчно.

## Внутренние источники проекта

`docs/IMPLEMENTATION_REPORT_v0.5.0_iretail_api_catalog_loyalty.md` фиксирует последовательность:

1. `POST /api/user/authentication`;
2. `POST /api/iretail/catalog/download-actual-zip`.

Текущий `IretailContentRepository` использует:

### Авторизация

- путь: `user/authentication`;
- метод: POST;
- тип тела: `application/x-www-form-urlencoded; charset=UTF-8`;
- поля: `username`, `password`, `client_id`, `client_secret`;
- из ответа читается `result.access_token`.

### Каталог

- путь: `iretail/catalog/download-actual-zip`;
- метод: POST;
- тип тела: `application/x-www-form-urlencoded; charset=UTF-8`;
- поля: `client_id`, `client_secret`, `access_token`, `channel_id`;
- ожидаемое тело успеха: ZIP;
- Android ожидает внутри `categories.json` и `offers_*.json`.

Windows/curl-аудит v0.5.40 повторяет **именно эту форму запросов**, не добавляя и не меняя серверные поля.

## Что проверяет аудит

1. Доступность самой актуальной документации.
2. Наличие используемых маршрутов/полей в загруженных материалах apiDoc.
3. HTTP-результат авторизации.
4. Наличие корректного `access_token` — только как признак, сам токен в отчёт не записывается.
5. HTTP-результат загрузки каталога.
6. Является ли ответ ZIP.
7. Размер, SHA-256 и список файлов ZIP.
8. Содержимое каталога сохраняется для анализа, но учётные данные и ответ авторизации не публикуются.

## Граница безопасности

Аудит не вызывает:
- создание заказа;
- синхронизацию заказа;
- лояльность;
- оплату;
- фискализацию;
- команды кофемашине.

Таким образом, это сетевой read-only аудит фактического контракта каталога.
