# Vendotek VT — результат TMS keepalive probe

Дата: 16.09.2026  
Архив: `VENDOTEK_TMS_20260916_144838.zip`  
Исходная ветка: `v0.5.27-vendotek-tms-probe`

## Итог

Один явно разрешённый человеком запрос `POS Management data = A` был передан терминалу по уже подтверждённому VTK/FTDI каналу.

До запроса:

```text
STATE=BUSY,NOT_READY;READY,DESCRIPTION=IN_SERVICE
```

Переданный кадр:

```text
TMS_KEEPALIVE_TX command=A
1f002096fb010349444c11143230323630393136543134343735312b303330301001415dbb
```

Vendotek почти сразу вернул корректный обычный `IDL`:

```text
1f000a97fb010349444c030130d90c
```

За следующие ~45 секунд не наблюдалось:

- подтверждения `A`;
- `CON`;
- `DAT`;
- `DSC`;
- Stage `921`;
- Stage `922`.

После наблюдения STATUS остался без изменений:

```text
STATE=BUSY,NOT_READY;READY,DESCRIPTION=IN_SERVICE
```

Диагностическая классификация:

```text
VTK_TMS_RESULT NO_TMS_ACTIVITY_OBSERVED
```

## Вывод

VTK framing, FTDI transport, IDL и STATUS продолжают работать штатно. Команда `A` не вызвала наблюдаемой TMS-сессии на этом экземпляре Vendotek и не вывела терминал из `IN_SERVICE`.

Этот результат не доказывает, что TMS функционально отсутствует. Возможные причины включают незарегистрированный/непровизионированный терминал, отсутствие TMS-профиля либо иной режим прошивки. Без дополнительных данных от поставщика это различить нельзя.

## Безопасность

В прогоне не было `VRP`, `FIN`, `ABR`, `DIS`, сверки, возврата или любой финансовой операции. Выполнена одна управляющая команда `A`, разрешённая оператором.

## Следующий шаг

Для удобства изоляции транспорта подготовлен прямой Windows COM probe. Аппаратный USB интерфейс терминала — FTDI FT232R (`VID:PID 0403:6001`). На Android/Linux он уже работает как `/dev/ttyUSB0`; на Windows тот же интерфейс должен появляться как `COMx` при установленном FTDI VCP-драйвере.
