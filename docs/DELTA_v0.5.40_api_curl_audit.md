# DELTA v0.5.40 — Windows/curl-аудит Retail API

Дата: 20.09.2026  
Основа: `v0.5.39-s2-catalog-diagnostics`.

## Основание и сверка с документацией

В техническом задании каноническим источником Retail API указан:

`https://my.i-retail.com/api/apidoc/actual/index.html`

Внутренняя документация проекта и реализация v0.5.0 фиксируют последовательность:

1. `POST /api/user/authentication`;
2. `POST /api/iretail/catalog/download-actual-zip`.

Текущий Android-клиент отправляет `application/x-www-form-urlencoded`.

### Авторизация

Поля:
- `username`;
- `password`;
- `client_id`;
- `client_secret`.

Из ответа используется `result.access_token`.

### Каталог

Поля:
- `client_id`;
- `client_secret`;
- `access_token`;
- `channel_id`.

Ожидаемый успешный ответ — ZIP с `categories.json` и `offers_*.json`.

Публичная страница документации из среды разработки сейчас напрямую не прочиталась. Поэтому новый Windows-аудит сначала сам сохраняет текущие `index.html`, `api_data.js` и `api_project.js` с канонического адреса документации, а затем выполняет те же запросы, что Android-приложение. После публикации отчёта эти файлы можно сравнить с фактическими вызовами без догадок.

## 🟢 Добавлено

- `RAPI_01_FETCH_DOCS_AND_TEST_CATALOG.bat` — один запуск проверки;
- `tools/iRetailApiCurlAudit.ps1` — выполнение вызовов через системный `curl.exe`;
- `RAPI_02_PUBLISH_LATEST_API_AUDIT.bat` — публикация последнего безопасного ZIP в Git;
- `tools/Assert-RetailApiAuditSafe.ps1` — проверка отчёта на утечку учётных данных;
- сохранение снимка актуальной документации Retail API;
- сохранение HTTP-кодов, времени ответа, типа содержимого и структуры результата;
- безопасная сводка ответа авторизации без `access_token`;
- SHA-256 и структура ZIP-каталога;
- санитарная выгрузка категорий и товаров без секретов;
- автоматическое сопоставление строк документации с двумя используемыми маршрутами.

## 🟡 Изменено

- номер диагностического выпуска: `0.5.40-api-curl-audit`;
- основной workflow проверяет наличие и безопасность Windows/curl-аудита.

## 🔴 Не добавлено

- никаких новых серверных маршрутов;
- никаких изменений параметров запросов Android;
- никаких запросов заказа, оплаты, лояльности или фискализации;
- никаких платёжных операций.

## ⚠️ Безопасность

Сценарий читает действующие параметры из `app/src/main/assets/content/iretail-api.json`, но:

- не печатает пароль, `client_secret` и `access_token`;
- сырое тело авторизации живёт только во временном каталоге Windows;
- в Git попадает только очищенный отчёт;
- перед публикацией ZIP повторно сканируется на фактические значения логина, пароля и `client_secret`;
- сырой ZIP-каталог не публикуется: в Git попадают SHA-256, список файлов и очищенные поля товаров/категорий.

## Цель приёмки

Отделить четыре возможных класса проблемы:

1. документация/маршрут изменились;
2. авторизация не работает;
3. каталог не скачивается;
4. каталог скачивается, но Android не может его разобрать/применить.
