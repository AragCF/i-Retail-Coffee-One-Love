# S3 — контролируемая положительная проверка FiscalGateway после реальной оплаты

Версия контракта: 1.0.1  
Версия проекта: 0.5.98  
Дата: 23.09.2026  
Статус: **APPROVED_FOR_ONE_ATTEMPT**

## Основание

Пользователь явно одобрил одну реальную карточную оплату по контракту 1.0.0 и дополнительно зафиксировал тестовый товар ценой ровно **1,00 ₽**.

Эта редакция только сужает разрешённый тест и не расширяет финансовые полномочия.

## Цель

Однократно доказать на живой JL22 цепочку:

`ручной выбор тестового товара 1 ₽ → ручное нажатие «Банковская карта» → Kozen/SmartSkyPOS APPROVED → RuntimeOrder=PAID → FiscalGateway → DRAFT_READY → fiscalization_dry_run.json`

При этом:
- настоящий Fiscal API не вызывается;
- `iretail/order/synchronize` не вызывается;
- приготовление не запускается;
- автоматический повтор PAYMENT запрещён.

## Разрешённый заказ

Ровно одна позиция:
- product_id: `s3-fiscal-positive-test-1rub`;
- название: `S3 TEST PRODUCT 1 RUB`;
- цена: 1,00 ₽ / 100 копеек;
- количество: 1;
- без карты лояльности;
- без бонусов;
- без купона;
- без сиропа;
- без своего стакана.

Тестовый товар существует только в специальном диагностическом режиме и не должен попадать в обычный каталог.

## Включение POS

`real_pos_enabled=true` разрешён только как параметр текущего запуска MainActivity.

Запрещено сохранять `true` в постоянные настройки машины. До теста и после теста сохранённое значение должно быть `false`.

При аварийном перезапуске приложения обычный запуск обязан вернуться к сохранённому `real_pos_enabled=false`.

## Инициация

- PAYMENT инициируется только человеком через основной интерфейс i-Retail;
- Windows-сценарий не отправляет PAYMENT;
- кнопка «Банковская карта» нажимается ровно один раз;
- после создания маркера повтор запрещён независимо от APPROVED/DECLINED/FAILED/UNCERTAIN.

## Двойной одноразовый предохранитель

Перед отправкой PAYMENT Android создаёт внутренний файл:
`files/fiscal_positive_payment_test_v1_0_1.attempt`.

После появления этого маркера Windows-сценарий создаёт локальный маркер использованной попытки в каталоге диагностических журналов.

Наличие любого маркера блокирует повторный запуск финансовой попытки.

## Предварительные блокировки

До создания маркера проверяются:
- debug-сборка;
- Standalone;
- runtime real POS=true;
- persisted real POS=false;
- отсутствие незавершённой предыдущей оплаты;
- точный состав заказа;
- сумма ровно 100 копеек.

## Ожидаемый APPROVED

1. Kozen возвращает достоверный APPROVED.
2. RuntimeOrder переводится в PAID.
3. FiscalGateway вызывается один раз.
4. Активен только DryRunFiscalGateway.
5. Возвращается DRAFT_READY, sendAllowed=false.
6. Создаётся локальный fiscalization_dry_run.json.
7. В нём проверяются catalog_id, цена 100, quantity=1, отсутствие модификаторов и card_amount=1.00.
8. Сетевого вызова Fiscal API нет.

## Любой финальный исход

Сразу после результата приложение локально выключает runtime real POS.

Windows-сценарий вторично сохраняет:
- machine_mode=standalone;
- real_pos_enabled=false.

После этого собирается санитизированный отчёт.

## Публикация

До публикации отчёта обязательны:
- удаление/маскирование RRN, authCode, receipt, terminalId, transactionId, paymentTid и длинных числовых последовательностей;
- проверка отсутствия PAN, track data, PIN, api_key, client_secret, access_token, device_code, external_code;
- SHA-256 архива.

При провале safety scan отчёт в Git не публикуется.

## Жёстко запрещено

- второй PAYMENT;
- автоматический retry;
- ручной повтор после UNCERTAIN;
- `iretail/order/synchronize`;
- боевой cloud-fiscal;
- device/register и external-system register;
- admin/device/create;
- операции смены;
- приготовление напитка;
- публикация карточных данных, секретов и идентификаторов, перечисленных выше.

## Условие приёмки

Положительный этап закрыт только если живой отчёт доказывает одновременно:
- ровно один PAYMENT_TX_ONCE;
- сумма 1.00;
- APPROVED;
- RuntimeOrder=PAID;
- FiscalGateway=DRAFT_READY;
- sendAllowed=false;
- fiscalization_dry_run.json соответствует тестовому товару;
- persisted real POS=false после завершения;
- safety scan пройден.
