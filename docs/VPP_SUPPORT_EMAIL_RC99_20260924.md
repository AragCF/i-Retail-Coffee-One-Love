# Письмо в техническую поддержку ВПП — SmartSkyPOS rc=99

Кому: support@payment-guide.ru  
Тема: Kozen P12 / SmartSkyPOS — устойчивый отказ rc=99, профиль VPP_BETA_TMS_V1

Здравствуйте.

Интегрируем Kozen P12 со SmartSkyPOS в составе автоматической кофейной точки Coffee One Love.

Просим проверить provisioning/acquiring-профиль нашего терминала.

Симптом:
- реальная карточная операция доходит до SmartSkyPOS;
- результат транзакции: approved=false, rc=99, message=«Отказано»;
- текущая контрольная сумма: 1,00 ₽;
- read-only getLastTransaction/getTransaction подтверждают тот же финальный результат.

Что уже проверено:
- SmartSkyPOS state=0 / READY;
- TerminalData code=0;
- операция payment доступна;
- валюта 643 доступна;
- USB/AOA-транспорт не является причиной: тот же rc=99 ранее получен при локальном вызове непосредственно на Kozen, без внешнего Android-хоста;
- в истории есть как минимум две разные суммы, завершившиеся rc=99.

Текущая конфигурация терминала:
- SmartSkyPOS 1.9.19-RC.1.11057-BETA;
- firmware 2.3.70.20250605;
- TMS profile: VPP_BETA_TMS_V1;
- profile active: да;
- host: 185.162.94.67;
- port: 9221.

Точные TID / merchant ID / TMS ID готовы передать инженеру по закрытому каналу.

Просим уточнить:
1. Что означает rc=99 в данном SmartSkyPOS/TMS-профиле?
2. Предназначен ли VPP_BETA_TMS_V1 для реальных банковских карт?
3. Требуется ли перевести терминал на production TMS/profile?
4. Корректна ли привязка TID/merchant к acquiring host?
5. Загружены ли рабочие криптографические ключи и банковский профиль?
6. После исправления можно ли выполнить одну контрольную операцию 1,00 ₽?

Автоматических повторов платежа с нашей стороны нет. До ответа поддержки новые финансовые операции остановлены.

Спасибо.
