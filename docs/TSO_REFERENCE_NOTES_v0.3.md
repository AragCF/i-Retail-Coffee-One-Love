# TSO Reference Notes для i-Retail Android UI v0.3

Документ фиксирует, что было полезно изучить в архиве `net.payinpayout.tso-master.tar.gz`, и как это влияет на дальнейшую Android-разработку.

## 1. Что это за архив

Архив похож на крупный терминальный/вендинговый проект i-Retail/TSO с конфигурациями, экранами, оплатой, лояльностью, кассой, торговым каталогом, кофемашиной, чайной/лимонадной станцией, служебными меню и установочными пакетами для Raspberry Pi / Windows.

Для текущего Android-приложения это не “готовая библиотека”, которую можно просто подключить. Это скорее источник:

- терминологии;
- сценариев;
- границ ответственности;
- настроек оборудования;
- будущих контрактов интеграции.

## 2. Полезные настройки из конфигураций

В конфигурациях найдены важные признаки, которые нужно учитывать в будущих контрактах:

- `mode="coffeemachine"` — режим кофейного/вендингового аппарата;
- `screenKeyboard="true"` — экранная клавиатура должна быть частью приложения;
- `isBasketBottom="true"` — корзина может быть нижней панелью;
- `shopItemClickMode="addToBasket"` / `openItem` — разный режим поведения карточки товара;
- `basketScenario` — отдельная логика корзинного сценария;
- `paymentButtonName`, `periodForPay`, `isUseNewOnlinePayment` — настройки оплаты;
- `maxBonusPayAmount`, `firstOrderUsePoints` — ограничения лояльности;
- `useOwnCup` — свой стакан для напитков;
- `coffee`, `tea`, `softDrinks`, `cups` — разные исполнительные подсистемы;
- `blockerScreenConfig` — экран блокировки/ошибки с QR-ссылкой поддержки;
- `mainScreenView` — параметры компоновки главного экрана.

## 3. Что уже отражено в Android UI v0.3

- Экранная клавиатура купона и лояльности работает без системной клавиатуры Android.
- Корзина хранит реальные выбранные товары, а не статичные позиции из PNG.
- Для напитков появилась локальная опция “свой стакан”.
- Для напитков появилась локальная опция “сироп добавлен”.
- Оплата, лояльность и выдача находятся за мок-шлюзами, чтобы позже заменить их боевыми адаптерами.

## 4. Что нельзя переносить напрямую

Не переносить напрямую в Android-приложение:

- Swing/desktop UI-код;
- старую конфигурационную систему целиком;
- dll/нативные Windows-зависимости;
- Raspberry shell-скрипты;
- кассовые и платёжные вызовы без отдельного контракта;
- протоколы оборудования без стендовой проверки.

## 5. Будущие адаптеры, которые нужно согласовать отдельно

- `CatalogGateway` — каталог, цены, доступность, изображения, модификаторы.
- `OrderGateway` — создание заказа, идемпотентность, статусы.
- `LoyaltyGateway` — карта, бонусы, скидки, ограничения.
- `PaymentGateway` — POS/наличные/онлайн-оплата, таймауты, отмена.
- `FiscalGateway` — создание/получение чека и QR.
- `CoffeeMachineGateway` — приготовление кофе через Raspberry Hub / JL22.
- `SoftDrinkGateway` — лимонадная или смесительная станция.
- `TeaStationGateway` — чайная станция.
- `KioskGateway` — служебные режимы, заставка, блокировка, восстановление после сбоя.
