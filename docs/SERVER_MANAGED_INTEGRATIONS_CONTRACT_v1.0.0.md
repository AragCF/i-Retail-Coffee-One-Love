# Server-managed integrations contract v1.0.0

Версия проекта: 0.5.126-server-managed-integrations  
Дата: 26.09.2026  
Статус: APPROVED

## 1. Цель

I-Retail становится источником истины для:
- каталога и доступности товаров;
- настроек канала, которые доступны через подтверждённый read-only API;
- перечня разрешённых способов оплаты;
- состояния программы лояльности.

Платёжные операции, фискализация и административные изменения I-Retail в этот выпуск не добавляются.

## 2. Каталог

Рабочий путь:

`user/authentication -> iretail/catalog/download-actual-zip(channel_id) -> validate -> cache -> UI`.

Правила:

1. Корректный пустой каталог является допустимым состоянием сервера.
2. Пустой каталог не должен заменяться локальным демонстрационным ассортиментом.
3. Последняя исправная серверная копия используется только при ошибке сети, авторизации, загрузки, разбора или повреждённой структуре ZIP.
4. Повреждённая новая выгрузка не заменяет исправный кэш.
5. При включённом удалённом каталоге встроенный XML не является аварийным источником товаров.
6. Встроенный XML допустим только когда удалённый I-Retail явно отключён конфигурацией.
7. Каталог должен периодически обновляться во время длительной работы киоска, а не только после запуска.

## 3. Конфигурация канала и способы оплаты

Рабочие read-only методы:
- `iretail/channel/get`;
- `iretail/channel/get-available-services-in`.

Приложение:
- читает доступные серверу `service-in`;
- не считает `content/pay-methods.xml` источником истины при включённом I-Retail;
- не разрешает выбрать способ оплаты, который отсутствует в серверном списке;
- при недоступности серверной конфигурации действует fail-closed: новая платёжная операция не разрешается;
- не выполняет create/update/enable/verify/bind/admin-операций.

На этом этапе наличие server service означает только «способ разрешён конфигурацией I-Retail». Оно не означает, что Android-адаптер платежа реализован.

## 4. Лояльность

Уже подтверждённый read-only путь:
`iretail/client/get-coupons-and-balance`.

Разрешено:
- найти клиента;
- показать состояние программы, баланс и купоны;
- прикрепить идентификатор клиента к локальному заказу.

Запрещено считать баланс разрешённой суммой списания.

До подтверждения серверного метода расчёта/применения скидки Android:
- не уменьшает сумму заказа по собственному правилу;
- не объявляет бонусы списанными;
- честно сообщает, что карта распознана, но списание ещё не подтверждено сервером.

## 5. Устройства и order/synchronize

До ответа I-Retail/получения административного доступа:
- рабочий `device_id` не меняется автоматически;
- `device/register` и `device/register-external-system` повторно не вызываются;
- `admin/device/create` не вызывается;
- `order/synchronize` остаётся выключен.

Для продолжения нужны подтверждённые:
- type_slug;
- device_id / device_inner_id;
- order_counter / operation_counter / refund_counter;
- shift_id / check_counter;
- правило регистрации устройства;
- service_in_slug для внешнего POS.

## 6. Безопасность

- Никакие финансовые запросы автоматически не повторяются после неопределённого результата.
- Access token не пишется в журнал.
- Пароли, client_secret, PIN и платёжные реквизиты не публикуются в диагностических артефактах.
- Перенос рабочих секретов из APK выполняется отдельным выпуском с безопасным способом provisioning; v0.5.126 не должен ломать существующий доступ к живому API до появления такого механизма.

## 7. Критерии приёмки v0.5.126

1. Проект собирается.
2. Валидный пустой ZIP-каталог принимается и заменяет прежний кэш.
3. При включённом I-Retail пустой каталог не рождает локальные кофейные товары.
4. Повреждённый ZIP не уничтожает последнюю исправную копию.
5. `get-available-services-in` читается без финансовых/административных мутаций.
6. UI блокирует способ оплаты, отсутствующий в server service list.
7. При ошибке чтения service list новая платёжная операция блокируется.
8. Локальное самостоятельное списание бонусов отключено.
9. Существующие Kozen/SBP диагностические контуры не получают новых финансовых вызовов.
10. Живая проверка на JL22 подтверждает каталог и server-managed service gating.
