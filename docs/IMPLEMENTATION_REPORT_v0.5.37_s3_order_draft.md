# Отчёт реализации v0.5.37 — S3 order draft

## Назначение

Подготовить первый безопасный шаг серверного заказа, не создавая реальные записи в I-Retail.

## Поведение

После формирования локального заказа и нажатия кнопки перехода к способам оплаты приложение:

1. создаёт обычный локальный `RuntimeOrder`;
2. строит локальный JSON-кандидат для будущей синхронизации;
3. проверяет сумму товарных строк против общей суммы;
4. сохраняет JSON во внутреннюю память;
5. **не выполняет сетевой запрос**;
6. открывает обычный экран выбора способа оплаты.

## Источник полей

Использованы только поля, ранее зафиксированные в `TSO_REFERENCE_NOTES_v0.4.md`. Неизвестные значения не подменены локальными догадками.

## Приёмка

Для аппаратной проверки используется:

`S3_01_BUILD_INSTALL_ORDER_DRAFT_AUDIT.bat`

Сценарий просит пользователя добавить товары и нажать только кнопку перехода к способам оплаты. Выбирать карту, наличные или онлайн-оплату не требуется. Затем сценарий извлекает `order_sync_draft.json` через `run-as` и упаковывает доказательства.

## Критерии успеха

В JSON должны быть:

- `mode = DRY_RUN_ONLY`;
- `send_allowed = false`;
- список товаров с offer_id, quantity и точной ценой;
- `lines_equal_gross = true`;
- список unresolved с id / employee_id / pin / wire / response.

## Прогресс

S3 на текущей подстадии «черновик заказа»:
- шагов: 4;
- реализовано программно: 3;
- остаётся: 1 живой прогон и разбор сформированного JSON;
- готовность подстадии: **75%**.

Реальную отправку заказа включать до разбора этого отчёта нельзя.
