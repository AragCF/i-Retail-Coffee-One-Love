# Vendotek — первая попытка поиска сервисной Wi-Fi сети

Дата: 15.09.2026  
Ветка: `v0.5.26-vendotek-service-wifi`

## Итог

Первая попытка `VENDOTEK_06_SERVICE_WIFI_DISCOVERY.bat` завершилась до начала сканирования Wi-Fi.

Причина — синтаксическая ошибка Windows PowerShell 5.1 при чтении исходника `VendotekServiceWifiDiscovery.ps1`. В скрипте присутствовала строка с русским текстом внутри регулярного выражения. На данной системе исходник UTF-8 без BOM был интерпретирован в другой кодировке, строковый литерал повредился ещё на стадии разбора синтаксиса.

Из-за этого:

- сканирование Wi-Fi не началось;
- Vendotek не подключался ни к одной сети;
- настройки терминала не менялись;
- VTK-сообщения не отправлялись;
- финансовые команды не отправлялись;
- каталог `vendotek_wifi_logs` не был создан, поэтому `GIT_118_PUBLISH_VENDOTEK_WIFI_RESULT.bat` закономерно сообщил `Folder not found`.

## Исправление

Версия сценария поднята до `v0.5.26.1`.

`VendotekServiceWifiDiscovery.ps1` сделан полностью ASCII-only, чтобы Windows PowerShell 5.1 не зависел от BOM/локальной кодировки исходника. Удалена локализованная проверка сообщения `netsh`; вместо неё сценарий всегда сохраняет сырые ответы `netsh` и определяет результат по реально разобранным строкам SSID.

Дополнительно введён отдельный результат `NO_SSIDS_PARSED`, чтобы отсутствие разобранных SSID не маскировалось под нормальный `NO_NEW_SSID_SEEN`.

## Безопасность

Исправленный сценарий по-прежнему выполняет только пассивный `netsh wlan show networks mode=bssid` на компьютере Windows. Он не подключается к сетям, не меняет настройки Vendotek и не взаимодействует с VTK/эквайрингом.
