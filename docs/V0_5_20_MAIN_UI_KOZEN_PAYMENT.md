# v0.5.20 — основной i-Retail UI → Kozen через USB/AOA

## Что изменено

В основной `MainActivity` подключён реальный клиент `KozenAoaPaymentClient` для карточной оплаты по цепочке:

`i-Retail UI на JL22 → USB/AOA → Kozen Payment Bridge → SmartSkyPOS`.

Старая фиктивная схема, где `PAYMENT_POS` автоматически считался успешным примерно через 2,6 секунды, для банковской карты отключена. Основной интерфейс завершает карточную оплату только после ответа production-моста со статусом `APPROVED`.

## Защита от двойного платежа

- перед `PAYMENT` выполняются `PING`, `INFO`, `GET_STATE` и свежий `GET_TERMINAL_DATA`;
- TID берётся из свежего `TerminalData`, а не зашивается в основной интерфейс;
- на один `requestId` отправляется не более одной команды `PAYMENT`;
- после попытки отправки `PAYMENT` транспортная ошибка становится `UNCERTAIN`, автоматического повтора нет;
- при тайм-ауте проверяется только `GET_PAYMENT_STATUS` того же `requestId`;
- незавершённый `requestId` сохраняется на JL22;
- при следующей попытке сначала восстанавливается статус предыдущего запроса;
- восстановленный старый `APPROVED` никогда не засчитывается как оплата нового заказа: новый платёж блокируется до восстановления соответствующего заказа;
- восстановленный определённый отказ снимает блокировку, но текущий клик всё равно не запускает новый платёж автоматически.

## Kozen bridge 0.5.2

Помимо защиты `BridgeActivity` от двойного запуска добавлена защита непосредственно в `ProductionBridgeService`: пока один AOA-сеанс жив, повторный старт сервиса не закрывает и не заменяет его. Также исключены параллельные повторные `bindService()` к SmartSkyPOS до получения первого callback.

## Безопасный режим по умолчанию

В этой ветке реальная карточная оплата в основном UI **выключена по умолчанию**. `MainActivity` включает её только при явном параметре запуска:

```text
real_pos_enabled=true
```

Обычный запуск приложения не может инициировать реальный `PAYMENT` из основного интерфейса. Это позволяет сначала проверить установку и пользовательский сценарий без финансовой операции.

Для безопасного стендового прогона:

```bat
call MAIN_18_SAFE_INSTALL_SMOKE.bat 192.168.1.192:5555 192.168.31.134:5555
```

После проверки:

```bat
call GIT_107_PUBLISH_MAIN_UI_SAFE_SMOKE.bat
```

## Пока не считается завершённым

v0.5.20 ещё не является полностью готовым кассовым контуром. Отдельно остаются реальная фискализация/чек РФ, промышленное восстановление связи заказа с уже одобренным платежом после перезапуска приложения, а также адаптеры Vendotek, СБП и Multicard.
