# S3_ADMIN_ACCESS_HUMAN_GATE_v0.5.78

Дата: 22.09.2026.

## Статус

**HUMAN_GATE_REQUIRED**

## Что доказано

1. Обычный API-доступ работает:
   - `user/authentication` → status=true;
   - access token и refresh token выдаются.

2. Обычный пользователь имеет только явно возвращённое право:
   - `right.managementOrderRefund` — «Возврат заказа».

3. Административный вход теми же реквизитами не работает:
   - `user/admin-authentication` → status=false;
   - access token не выдаётся.

4. Поэтому:
   - `user/get-permissions` для admin token не выполнялся;
   - `user/get-profile-list` для admin token не выполнялся;
   - `admin/device/find` корректно не выполнялся.

5. Ранее прямые вызовы `admin/device/*` с обычным токеном возвращали status=false / permission denied.

6. Документация подтверждает, что создание кассового устройства выполняется через:
   - `/api/admin/device/create`.

7. Документация также содержит:
   - `/api/admin/device/repeat-activation` — реактивация и генерация нового code;
   - `/api/user/admin-authentication` — отдельная административная авторизация.

## Что пока НЕ доказано

- существует ли device 6287;
- существует ли уже `workplace_cashier` или `self_service_terminal`;
- можно ли создать кассу текущей учётной записью;
- какой именно административный пользователь имеет права на нужный профиль/channel;
- какой device type следует выбрать для Coffee One Love — это должно решаться после административной инвентаризации, а не угадываться.

## Следующий допустимый шаг

Нужен один из двух вариантов:

### Вариант A — есть административный доступ

Войти в административную панель I-Retail и проверить:
- список устройств профиля 2512 / канала 5676;
- наличие `workplace_cashier` / `self_service_terminal`;
- наличие или отсутствие device 6287;
- права текущего администратора на создание устройств.

После этого можно продолжать автоматический read-only аудит с административным token.

### Вариант B — административного доступа нет

Запросить у I-Retail:
- административный доступ к профилю/каналу;
- либо создание кассового/self-service устройства на их стороне;
- либо официальный способ получить/активировать такой device для интеграции.

## Жёсткие запреты до снятия human gate

- не вызывать `admin/device/create`;
- не вызывать `admin/device/update`;
- не вызывать `admin/device/repeat-activation`;
- не повторять `device/register`;
- не повторять `device/register-external-system`;
- не отправлять `order/synchronize`;
- не менять рабочий device_id приложения;
- не публиковать логины, пароли, токены, device_code/external_code.

## Что нужно от человека

Нужно только определить, существует ли отдельный административный доступ I-Retail.

**Не присылать пароль в чат.**
Если доступ есть, достаточно подтвердить наличие административного кабинета/учётной записи; дальнейший безопасный способ проверки будет подготовлен отдельно.
