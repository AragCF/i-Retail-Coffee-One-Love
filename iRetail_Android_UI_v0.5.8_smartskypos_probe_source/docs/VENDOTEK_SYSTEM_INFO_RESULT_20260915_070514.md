# Vendotek — результат System Information и текущее состояние готовности

Дата: 15.09.2026  
Исходный архив: `VENDOTEK_SYSTEM_INFO_20260915_070514.zip`  
Предыдущая ветка: `v0.5.24-vendotek-system-info`

## 1. Подтверждённый транспорт

Реальный терминал подключён к JL22 через USB/FTDI FT232R (`0403:6001`), Linux-драйвер `ftdi_sio`, устройство `/dev/ttyUSB0`, режим `115200 8N1`, без управления потоком.

VTK работает двусторонне. Обычный IDL получает корректный ответ POS с `0x97FB` и валидным CRC16.

## 2. Фактический STATUS

В двух независимых прогонах терминал вернул одинаковую системную информацию:

```text
STATE=BUSY,NOT_READY;READY,DESCRIPTION=IN_SERVICE
```

По VTK-MAN-RU 1.0 ответы STATUS могут содержать комбинации состояний. `BUSY` означает выполнение задачи, а `IN_SERVICE` указан как причина сервисного режима. Наличие `READY` в комбинированной строке не отменяет одновременно присутствующие `BUSY` и `NOT_READY`, поэтому текущая интеграция правильно запрещает финансовый VRP в таком состоянии.

## 3. Экран отсутствует — это нормальный вариант Vendotek

Физический терминал пользователя не имеет дисплея и использует только светодиодные индикаторы. Это совместимо с семейством Vendotek VT: руководство VTK отдельно указывает VT как вариант без экрана. Для VT/VTKPOS-V2 сервисные настройки могут выполняться через Wi-Fi/удалённое меню, а производитель также предусматривает настройку через TMS.

Следовательно, термин `IN_SERVICE` не следует трактовать как обязательно видимое меню на собственном дисплее устройства.

## 4. POS_PARAMS / BANK_PARAMS / NET_PARAMS

После каждого из запросов:

- `POS_PARAMS`;
- `BANK_PARAMS`;
- `NET_PARAMS`

терминал быстро присылал обычный корректный IDL без тега `SystemInformation (0x12)`. После этого отдельного ответа с `SystemInformation` в течение 8 секунд не приходило.

Это не обрыв UART и не ошибка CRC. Практически это означает: текущая прошивка/режим терминала не возвращает данные на эти запросы в данном состоянии. Руководство прямо предупреждает, что поддерживаемый набор команд зависит от модели и реализации ПО.

## 5. Что уже доказано

- JL22 видит реальный Vendotek по USB;
- FTDI и `/dev/ttyUSB0` работают;
- процесс i-Retail может читать и писать tty;
- настройка serial через factory `su` работает;
- VTK framing/BER-TLV/CRC16 проверены на опубликованных эталонах;
- IDL работает на реальном терминале;
- запрос `STATUS` работает;
- финансовых команд в диагностике SystemInfo не отправлялось.

## 6. Следующий безопасный шаг

Перед первым VRP необходимо отделить временное сервисное состояние от постоянной настройки. Подготовлен `VENDOTEK_05_READY_AFTER_REBOOT.bat`.

Он запускается после холодного перезапуска только Vendotek и в течение примерно 80–100 секунд отправляет исключительно `IDL` и `SystemInformation=STATUS` с интервалом не менее 10 секунд.

Критерий разрешения следующего финансового этапа: минимум два последовательных чистых ответа READY без `BUSY`, `NOT_READY`, `DISABLED` и `IN_SERVICE`.

Если `IN_SERVICE` останется во всех выборках после холодного запуска, дальнейшая работа должна перейти к настройке самого Vendotek через его Wi-Fi/TMS, а не к попыткам обойти состояние протоколом VTK.
