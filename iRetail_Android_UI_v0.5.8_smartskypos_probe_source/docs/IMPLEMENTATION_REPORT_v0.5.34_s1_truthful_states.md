# Отчёт реализации i-Retail v0.5.34 — этап S1

## Результат

Первый программный этап утверждённого контракта 1.1.0 реализован: приложение больше не должно выдавать неподтверждённую оплату, локальную псевдофискализацию или фиктивный успех исполнительного оборудования за реальный результат.

## Что изменено

1. **Оплата Kozen**
   - существующий реальный Kozen-клиент сохранён;
   - при достоверном одобрении заказ отмечается как оплаченный;
   - фискальный чек не считается сформированным автоматически.

2. **Наличные и онлайн-оплата**
   - до подключения реального подтверждаемого контура не запускают локальный успех;
   - таймеры завершения отключены;
   - статичный QR/фон не считается доказательством оплаты.

3. **Фискализация и email-чек**
   - удалена локальная ссылка `local://receipt/...`;
   - состояние `FISCALIZED` больше не присваивается локальным завершением оплаты;
   - нажатие «Отправить чек» не показывает ложный экран успешной отправки.

4. **Выдача, стакан и разогрев**
   - локальный исполнитель возвращает честное «не подключено»;
   - таймер автоматического завершения выдачи удалён;
   - экран завершения разогрева открывается только после положительного результата исполнителя.

5. **Проверка сборки**
   - добавлено 14 статических проверок ключевых инвариантов S1;
   - они запускаются до Android-сборки;
   - GitHub Actions успешно собрал debug APK.

- Реальный исполнитель и кассовый адаптер — S5.
- Структура каталогов проекта.

## Что проверить на устройстве

Без проведения новой финансовой операции можно проверить:
- наличные не завершаются успешно сами;
- онлайн-оплата не завершается по таймеру;
- отправка чека не показывает ложный успех;
- разогрев не показывает завершение без реального исполнителя;
- сценарий стакана не запускает фиктивную выдачу.

Проверку реального Kozen следует выполнять только как отдельный контролируемый платёжный тест, если он действительно нужен на этом шаге.
