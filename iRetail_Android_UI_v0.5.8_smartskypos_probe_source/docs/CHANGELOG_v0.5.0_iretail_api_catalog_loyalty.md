# i-Retail Android UI v0.5.0 — I-Retail API каталог и первый контур лояльности

## Что сделано

1. Добавлен сетевой контур I-Retail:
   - авторизация через `user/authentication`;
   - терминальные ключи `IRETAIL_TERMINAL`;
   - загрузка каталога через `iretail/catalog/download-actual-zip`;
   - разбор ZIP-каталога `categories.json` и `offers_0000.json`.

2. Меню больше не зависит только от PNG-макета и XML из TSO:
   - при наличии сети приложение загружает актуальный каталог I-Retail;
   - сохраняет ZIP-каталог в локальный кэш;
   - при отсутствии сети показывает последний сохранённый каталог;
   - если кэша ещё нет, возвращается к локальному XML-макету.

3. Живые карточки товаров теперь рисуются поверх макета:
   - название;
   - объём/единица;
   - цена;
   - изображение товара из I-Retail, если оно есть;
   - локальная картинка-заглушка, если изображение недоступно.

4. Добавлен первый контур лояльности:
   - поиск клиента через I-Retail/i-Bonus-прокси по введённому коду/телефону/email;
   - безопасный локальный демонстрационный режим, если тестовый клиент не найден;
   - задел под отображение баланса клиента.

5. Добавлен файл настройки:

`app/src/main/assets/content/iretail-api.json`

В нём лежат параметры демо-подключения: адрес API, логин, пароль, `client_id`, `client_secret`, `profile_id`, `channel_id`, `currency_id`.

## Проверено

- Выполнена статическая компиляционная проверка Kotlin-файлов через локальные Android-заглушки.
- Синтаксических ошибок в изменённых Kotlin-файлах не найдено.
- Полную Gradle-сборку APK в этой среде выполнить нельзя: здесь нет Android SDK и Gradle.

## Важное ограничение

Клиентская лояльность пока не подтверждена на реальном тестовом покупателе, потому что нет тестового телефона/email/QR/token клиента. Поэтому в приложении есть сетевой запрос и безопасный демонстрационный возврат, но финальный сценарий списания/начисления бонусов нужно добить после получения тестового клиента.
