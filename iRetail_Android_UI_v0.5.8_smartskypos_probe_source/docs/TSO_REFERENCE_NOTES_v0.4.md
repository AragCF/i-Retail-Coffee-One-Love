# Что найдено в `net.payinpayout.tso-master.tar.gz` и как это использовано в Android UI v0.4

## Использованные XML-данные

### `content/main-screen.xml`

Файл содержит список разделов и предложений. Для v0.4 из него взяты кофейные товары по признаку названия/объёма, например:

- Американо 200мл;
- Американо XL 300мл;
- Какао 200мл;
- Капучино 200мл;
- Капучино XL 300мл;
- Латте 300мл;
- Флэт Уайт 200мл;
- Эспрессо 100мл.

Из каждого предложения используются:

- `offerId` — будущий идентификатор товара в заказе;
- `caption` — название;
- `price` — цена;
- `currency` — валюта.

### `content/pay-methods.xml`

Файл содержит доступные способы оплаты. В v0.4 он используется для подписей и будущей связи экранов оплаты с реальными `service_in_id`/`slug`.

## Найденные серверные команды TSO

По исходникам TSO выделены ключевые команды:

- `order/reserve-order-id` — резервирование номера заказа;
- `order/create` — создание заказа;
- `order/pay` — оплата заказа;
- `order/get-by-id` — получение состояния заказа;
- `iretail/channel/get-available-services-in` — способы оплаты;
- `iretail/order/create-payment-for-order` — создание онлайн-платежа;
- `iretail/check/send` — отправка чека;
- webhook приготовления кофе — старт, успешное завершение, неуспешное завершение, процент готовности.

## Поля заказа, которые нужно сохранить для боевого этапа

В классе `CreateOrderRequest` важны поля:

- `id`;
- `channel_id`;
- `sum`;
- `device_id`;
- `device_code`;
- `employee_id`;
- `pin`;
- `currency_id`;
- `time_create`;
- `products[].offer_id`;
- `products[].quantity`;
- `products[].price`.

В v0.4 эти поля не отправляются наружу, но модель заказа уже хранит локальный номер, сумму и список товаров с `offerId`.

## Логика приготовления кофе

В TSO-проекте есть класс `CoffeeMaker`, который запускает приготовление через `makeCoffee(...)`. По коду видна важная бизнес-логика:

1. проверяется готовность к приготовлению;
2. учитывается наличие/готовность стакана;
3. выбирается кофейная позиция и её параметры;
4. отправляется стартовый webhook;
5. запускается приготовление на кофемашине;
6. отправляется успешный или ошибочный webhook с процентом готовности и текстом ошибки.

В v0.4 эта логика отражена только как локальное состояние `COOKING → READY`. Реальную команду JL22 нужно подключать после согласования протокола и транспортного слоя.

## Что не переносилось напрямую

Не переносились:

- настройки с адресами, токенами, ключами и PIN;
- прямые сетевые клиенты TSO;
- файловое хранилище TSO;
- POS/MDB/кассовые драйверы;
- команды реального оборудования.

Причина: это другая среда исполнения, и часть настроек может быть привязана к стенду или содержать чувствительные данные. Для Android-приложения безопаснее взять форму данных и сценарии, а реальные адаптеры подключить явным контрактом.
