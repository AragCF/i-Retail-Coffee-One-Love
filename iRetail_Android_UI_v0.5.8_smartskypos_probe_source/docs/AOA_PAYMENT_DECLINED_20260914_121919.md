## Примечание к полю code

В текущем мосте v0.4.x отсутствующий ключ `code` читался через `Bundle.getInt("code", Integer.MIN_VALUE)`, поэтому в журнал попало `code=-2147483648`. Это диагностический sentinel нашего моста, а не подтверждённый код SmartSkyPOS. В восстановленном клиентском контракте `TransactionResult.getCode()` использует `Bundle.getInt("code")`, то есть при отсутствующем ключе возвращает `0`.

Поэтому следующий безопасный шаг — не новый платёж, а отдельное read-only чтение `getLastTransaction()` и затем `getTransaction()` по найденному номеру чека через JL22 → AOA → Kozen. В recovery-пакете финансовых Binder-команд нет.
