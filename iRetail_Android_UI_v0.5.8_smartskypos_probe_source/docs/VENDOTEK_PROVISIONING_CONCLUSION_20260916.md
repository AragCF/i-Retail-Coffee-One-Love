# Vendotek VT — вероятный блокер: провизионирование / эквайринг / TMS

Дата: 16.09.2026  
Основание: результаты веток `v0.5.23`–`v0.5.28`

## Краткий вывод

На текущем этапе наиболее вероятный класс проблемы — **не отсутствие связи с Vendotek и не ошибка VTK-транспорта, а состояние провизионирования самого терминала**: терминал может быть не зарегистрирован в TMS, не привязан к тестовому эквайрингу/платёжной системе, не иметь загруженного банковского профиля, TID/MID, ключей или сетевых параметров.

Это пока не доказано окончательно без данных поставщика/эквайера, но хорошо согласуется со всеми наблюдениями.

## Что уже доказано рабочим

1. Аппаратный интерфейс терминала — FTDI FT232R, `VID:PID 0403:6001`.
2. На JL22 он штатно появляется как `/dev/ttyUSB0`.
3. Последовательный режим `115200 8N1`, без управления потоком, работает.
4. VTK framing работает в обе стороны:
   - `0x1F`;
   - `0x96FB` VMC→POS;
   - `0x97FB` POS→VMC;
   - BER-TLV;
   - CRC16-CCITT.
5. `IDL` стабильно получает корректный ответ.
6. `STATUS` стабильно получает корректный ответ.
7. После холодной перезагрузки терминала состояние не меняется и восемь последовательных раз возвращается:

```text
STATE=BUSY,NOT_READY;READY,DESCRIPTION=IN_SERVICE
```

8. `POS_PARAMS`, `BANK_PARAMS`, `NET_PARAMS` не возвращают SystemInformation на этом экземпляре: терминал отвечает обычным `IDL`.
9. Один явно разрешённый оператором запрос TMS keepalive (`POS Management data = A`) был принят транспортом, но за ~45 секунд не было `CON`, `DAT`, `DSC`, Stage `921/922`, подтверждения `A` или изменения STATUS.
10. Пассивный поиск Wi‑Fi не обнаружил отдельной точки доступа Vendotek при включении терминала.

## Почему это похоже именно на отсутствие провизионирования

Рабочий VTK-канал доказывает, что физический USB/COM транспорт и базовый протокол исправны. При этом терминал устойчиво сообщает одновременно `BUSY`, `NOT_READY` и `IN_SERVICE`, то есть сам не считает себя готовым к штатной продаже.

Если терминал не зарегистрирован в TMS или не получил профиль эквайринга, типично могут отсутствовать или быть неактивны:

- тестовый/боевой TID;
- MID/merchant profile;
- банковское приложение или профиль эквайера;
- криптографические ключи;
- адреса/параметры процессинга;
- сетевой профиль;
- разрешённые операции;
- активация терминала в TMS.

В таком состоянии отправлять первый финансовый `VRP` преждевременно: даже правильно сформированный запрос не докажет качество нашей интеграции, пока сам POS остаётся `NOT_READY / IN_SERVICE`.

## Что нужно запросить у поставщика Vendotek / эквайера

Для нашего экземпляра необходимо уточнить и, при необходимости, выполнить:

1. Зарегистрировать терминал в TMS.
2. Привязать его к **тестовому** эквайринговому/платёжному контуру.
3. Назначить тестовые `TID` и `MID` (если используются этой конфигурацией).
4. Загрузить/активировать профиль банка/эквайера и разрешённые операции продажи.
5. Загрузить необходимые криптографические ключи/сертификаты, если они не загружены.
6. Настроить сетевой/TMS профиль терминала.
7. Сообщить штатную процедуру активации сервисной Wi‑Fi точки для безэкранного VT, если она требуется.
8. Сообщить ожидаемую строку `STATUS` для полностью готового терминала.
9. Подтвердить, должен ли `POS Management data = A` запускать TMS-сессию на данной прошивке/конфигурации.
10. Сообщить, какие `POS_PARAMS`, `BANK_PARAMS`, `NET_PARAMS` должны поддерживаться на этой версии VTKPOS.

## Идентификаторы для поставщика

Аппаратный экземпляр на фотографии имеет наклейку:

```text
220000047601
```

Эту величину пока следует называть **маркировкой/серийным номером с наклейки**, а не протокольно подтверждённым `SN`, потому что текущий терминал не вернул `POS_PARAMS`.

USB/FTDI:

```text
VID:PID = 0403:6001
FTDI FT232R USB UART
```

Текущее VTK состояние:

```text
STATE=BUSY,NOT_READY;READY,DESCRIPTION=IN_SERVICE
```

TMS keepalive:

```text
POS Management data = A
result: plain IDL only
CON/DAT/DSC: none observed
Stage 921/922: none observed
STATUS after request: unchanged
```

## Рекомендуемое продолжение после провизионирования

После подтверждения со стороны поставщика, что терминал привязан к тестовому контуру:

1. Холодно перезапустить Vendotek.
2. Повторить `IDL` + `STATUS`.
3. Требовать два последовательных чистых состояния `READY` без `BUSY`, `NOT_READY`, `DISABLED`, `IN_SERVICE`.
4. Снова проверить SystemInfo, если прошивка поддерживает его.
5. Только затем выполнить один staged `VRP` на 1 ₽ с уникальным operation number.
6. Не повторять финансовую операцию автоматически при неопределённом результате.
7. Завершать `FIN` только по правилам VTK и фактическому результату выдачи/продажи.

## Состояние прямого Windows COM-теста

Ветка `v0.5.28-vendotek-windows-com` содержит прямой Windows COM probe для FTDI VCP. Он выполняет только `IDL` и `STATUS` и нужен для полной изоляции JL22 от транспортной цепочки.

На момент формирования этого документа свежий архив результата `VENDOTEK_COM_*.zip` ещё не опубликован в удалённой ветке. Поэтому результат этого отдельного COM-теста в вывод выше не включён.
